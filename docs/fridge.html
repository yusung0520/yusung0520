6인 팀 프로젝트

냉장고를 부탁해

보유 식재료의 소비기한을 관리하고, 사용자가 선택한 재료로 레시피를 추천합니다.

담당
팀장, 소비기한 정책과 레시피 백엔드
사용 기술
Spring Boot / JPA / MariaDB

시작한 이유

같은 두부를 두 번 샀더라도 소비기한은 다를 수 있습니다. 프론트엔드 팀원과 추천 요청의 입력을 식재료 ID 목록으로 정해, 사용자가 고른 항목을 서버에서도 구분할 수 있게 했습니다.

소비기한 당일은 임박일까, 만료일까?

기한까지 남은 날짜가 0~5일이면 임박, 이미 지났으면 만료로 분류합니다. 오늘 날짜는 Clock으로 주입해 테스트에서 기준 날짜를 고정하고, 당일과 기한 경계에서 결과가 달라지는지 확인할 수 있게 했습니다.

추천 요청에서는 빈 목록과 유효하지 않은 ID를 먼저 검사합니다. 서비스는 로그인한 사용자의 식재료만 조회하고, 조회한 ID 집합과 요청한 ID 집합이 일치하는지 검사합니다.
